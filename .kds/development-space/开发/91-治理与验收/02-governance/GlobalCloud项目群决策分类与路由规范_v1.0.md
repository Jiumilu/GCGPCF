# GlobalCloud 项目群决策分类与路由规范

日期：2026-10-23
状态：v1.1（运行侧已启用）
适用范围：GlobalCloud 项目群 28 个项目的决策判定、路由、留痕与复核
依据：老卢 2026-10-22 确认 B 方案；StartLux-Decision v1.1 判定 0.929（none_p 0.0021）；决策模型权责见 `constitution-governance-responsibility.md` 决策模型权责裁定（2026-10-22）

## 1. 目的

把项目群决策从「经验拍板」变为「可分类、可路由、可复核」。

**分类的价值不在标签本身**，而在于每条决策因此获得不同的处置链：谁拍板、要什么证据、走哪条闸门、记什么字段。不改变处置链的分类是装饰，不是治理。

## 2. 判定顺序（固定）

```
gate(redline)  →  decision_class  →  authority / reversibility / horizon  →  rate(urgency|risk)
   保底               定路由                    定处置约束                        定优先级
```

先问「能不能做」，再问「是什么」，最后问「多急」。顺序不可颠倒。

## 3. 对象轴：6 类（一条决策只落一类）

判据取「若判错，最坏后果落在哪里」；纯事实或风险陈述不是待决事项，须先转成「要不要做 / 怎么做」的动作表述再判。

| 类 | 判据 | 典型事项 | 默认拍板 |
|---|---|---|---|
| `tech` 技术实施 | 改代码、配置、部署、数据结构、依赖或发布物 | 生产配置固化、数据迁移、服务发布、架构与接口调整 | 执行 Agent；生产环境→老卢 |
| `business` 产品业务 | 改对外承诺、交付范围、价格、合同或客户关系 | 报价让价、范围裁剪、合作模式、对外交付宣称 | 老卢 |
| `governance` 治理合规 | 改「谁能做什么」或「账本口径」 | 立项/注销/改名/归属、权限、红线定义、宪法条款、数据与检索范围规则、授权签发 | 老卢 |
| `ops` 运营运维 | 维持运行，不改变范围与承诺 | 巡检异常处置、故障修复、备份恢复、告警响应、发布节奏 | 执行 Agent / 值班 |
| `resource` 资源财务 | 占用有限资源（资金、注意力、并行执行流、时间窗） | P0 取舍、预算、采购、人力分配、窗口期取舍 | 老卢 |
| `personal` 个人私有 | 决策对象是老卢个人或家庭事务本身 | 健康、家庭沟通、私人安排、个人时间 | 老卢本人 |

**隔离约定**：`personal` 为隔离类，**不进项目群决策集与一致率校准**，台账打 `scope=personal`，与 KDS personal 层默认 `rag_include:false` 口径一致。

**边界纠正**：「个人数据如何处理」属 `governance`（如 personal 层是否默认不进检索），不属 `personal`。

## 4. 横切轴：3 标签（与对象轴正交）

| 标签 | 取值 | 用途 |
|---|---|---|
| `authority` 授权级别 | `auto` / `agent` / `laolu` / `external` | 决定谁拍板、是否停 |
| `reversibility` 可逆性 | `two_way` 可回滚 / `one_way` 不可逆 | `one_way` 必须停下并留痕 |
| `horizon` 时限 | `today` / `week` / `quarter` / `none` | 决定排期与是否可延后 |

`horizon` 仅在输入含时限信息时调用；输入无时限时模型置信度显著下降（实测 conf 0.16），应留空或先补时限，不得强行填写。

## 5. 路由与兜底规则

1. **混合事项先拆分**：同时含技术动作与对外承诺的，拆成两条分别判（发布=`tech`，对外宣称=`business`）。
2. **拆分信号**：`top1 < 0.7` 且 `top2 > 0.25` → 不硬判，先拆事项。
3. **事实不等于决策**：纯事实/风险陈述先转成动作表述（如「PMC 没有定时备份」→「是否立即加定时备份」）。
4. **兜底闸门**：`none_probability > 0.2` → 转人工，不硬用结果。
5. **选项集缺口**：真实选择不在所给选项内时，记复核驳回并补选项，不硬套最接近的选项。

## 6. 红线九条（2026-10-23 定稿）

红线由五条扩为九条（2026-10-22 老卢确认扩条；2026-10-23 定稿），统一由 `gate(redline)` 判定：

| 条款 | 内容 | 关键例外 |
|---|---|---|
| ① 删除 | 任何数据/功能/文件删除 | 单条/单仓可再生物、死代码/重复入口免；批量/跨仓/>100 文件/git rm 产提交仍需确认；`_archive`/历史快照不算可再生物 |
| ② 资金 | 资金支出、付款、报价调整或让价（含降价、折扣、返点、账期放宽） | — |
| ③ 治理 | 改架构/宪法/职责/架构级治理口径；跨项目共享组件；批量授权签发；写入/发布治理与状态正式文档（含本地 09-status） | 纯措辞修订免 |
| ④ 对外 | 对外发送文件或承诺 | — |
| ⑤ 立项 | 项目立项、注销、改名 | — |
| ⑥ 生产 | 改生产配置/数据、数据库迁移、同机部署新服务 | 代码发布/容器重建/重启/回滚不改配置数据免；含配置或数据改动即使伴随发布也须确认 |
| ⑦ 密钥 | 写入/复制/外发密钥、凭据、口令、证书 | 不限环境 |
| ⑧ 主分支 | 合并 main/release、跨项目合主干、push 到已配 CI 的远端 | 未配 CI 的私有远端 push 免 |
| ⑨ 工作区 | 迁移/移动仓库或 worktree、改工作区目录结构 | 普通文件移动免 |

### 6.1 闸口灰区（2026-10-22 实测）

| p 区间 | 处置 |
|---|---|
| p < 0.3 | 自动放行 |
| 0.3 – 0.7 | **灰区：必须人工** |
| p > 0.7 | 自动判停 |

同一输入多次运行结果一致；不同措辞可差 0.2+，故不逐条调措辞。

### 6.2 输入契约（tech 必填）

`env` · `change_types` · `project_action` · `authorized` · `triggers_ci`

- MCP 工具 `gate_contract(change)` 直接接收结构化契约；
- 缺 `authorized`/`triggers_ci` 时不得硬判，历史决策可由老卢**人工确认后回填**
  （`~/.cache/startlux/contract-overrides.jsonl`，带 confirmed_by 与时间，不改原始 state）。

### 6.3 验证结果

| 事项 | 判定 |
|---|---|
| 生产 Caddyfile 固化并重启 | 0.97 须确认 |
| 生产数据库迁移 | 0.98 须确认 |
| 授权批次内纯代码发布 | 0.11 放行 |
| 生产 30 天前日志清理（自动化） | 灰区，人工 |

红线覆盖矩阵（九条 × 25 样例）清晰区 22/22；一致性审计（97 条人工标签）补契约后 79/79。
开发/测试/本地环境不受⑥影响。

## 7. 台账与复核

1. **台账**：`~/logs/startlux/decisions.jsonl`，append-only；schema v2 起 `decision` 行带 `decision_class` / `authority` / `reversibility` / `horizon` / `scope`，旧行缺失按 null 处理，不改写。
2. **人类裁决留痕**：复核追加 `review` 行（采纳/驳回/存疑）；结果回填追加 `outcome` 行（`ok` / `rework` / `regret` / `unknown`），建议判定后 30 天回填。
3. **复核抽样优先级**：`needs_human` > 闸口 p 0.3–0.7 > 分类低置信 < 0.5 > 中置信/定级档位模糊。随机抽样价值显著低于边缘抽样。
4. **首个基线**（2026-10-22）：首批 4 条项目决策复核，3 采纳 1 驳回；累计一致率 8/9 = 88.9%。驳回项暴露「选项集缺口」并已补规则。

## 8. 职责边界

- 模型结果只作初筛、闸口建议与定级参考，**不得作为授权、放行或状态提升依据**；人工裁决不可替代。
- 运行、发布与许可由 WAME 承担；治理口径与决策台账由 GPCF 承担（见决策模型权责裁定）。
- 权重许可为 CC BY-NC 4.0：仅限内部使用，不得进入对外商业交付；商业化须先取得 StartLux 书面授权。
