# 世界资产浏览器（WAE）总体方案候选 v1.0（2026-10-22）

> **文档性质**：候选方案（`status: candidate`、`confirmed: false`）。
> **不构成**：项目群权威方案、WAE 项目状态提升、任何项目 `accepted` / `integrated` / `production_ready` / `customer_accepted`。
> **生效条件**：老卢确认 → WAE 属主在 WAE 仓落唯一总体方案 → 更新 `09-status/globalcloud-project-master-plan-control-register.md` 并由台账核验。在此之前，本文件仅是**待确认候选**。

## 1. 定位

WAE（World Asset Explorer，世界资产浏览器）是 **GlobalCloud 项目群统一界面壳层与统一入口**：

1. 统一壳层：`app-shell`（外壳/骨架）+ `ui-tokens`（令牌）+ `ui-kit`（组件）+ `app-registry`（应用注册与入口导航）；
2. 统一入口：项目群各应用的装配登记、入口导航、身份上下文与状态展示；
3. **承接 Studio 作废后的工作台壳层职责**（老卢 2026-10-22 决策，见 `docs/harness/evidence/studio-retirement-alternative-plan-20261022.md`）。

一句话：**WAE 统一"壳、令牌、组件、入口、状态语义"，不统一业务主账、治理裁决与运行引擎。**

## 3. 边界

### 3.1 与相邻系统的边界（不越权）

| 相邻系统 | 对方权威 | WAE 只做 | 不做 |
|---|---|---|---|
| **WAME**（世界资产模型引擎／母本） | 资产主账、运行引擎、治理执行、注册/授权/发布 | 以 WAME/WAES 母本框架层为起点做**直出 + 最小改造**；装配登记与入口 | 不持资产主账、不做治理裁决、不替代 WAME 引擎 |
| **Hermes Web UI**（Agent 对话与运行时入口） | Agent 对话、技能、运行时 UI、运行观测 | 统一入口内的**入口链接或受控内嵌** | 不重写对话/技能/运行时 |
| **PMC / Plane**（项目协作） | 工作项、项目协作、只读投影 GPCF 交付状态 | 统一入口内的**入口或只读内嵌** | 不持工作项主数据、不替代 PMC 协作 |
| **GPCF Console（F-018）** | Feature/Evidence Gate、治理/发布控制台 | 统一入口内承接**只读治理视图** | 不替代 GPCF 门禁与状态裁决 |
| **WAS / World / 各业务项目** | 业务主账、业务页面、独立运行边界 | 通过 `app-registry` 装配与导航；档次 A/B 例外机制 | 不改各项目业务主账；不以装配登记替代集成验收 |
| **Studio**（`deprecated`，2026-10-22 冻结） | — | 承接其工作台壳层职责 | 不新开 Studio UI 工作、不修复其回归（另立任务/由属主裁决） |
| **PVAOS** | 租户、组织、伙伴、用户、门户配置 | 消费身份上下文（`/api/idp/*`） | 不持租户/身份权威 |

### 3.2 范围 / 非范围

**范围（in）**：

1. 统一壳层：外壳/骨架、令牌、组件层、应用注册与入口导航；
2. 统一状态语义：7 值状态字典 + 证据语义边界（S1/S2/S3）；
3. 装入与接入：装配登记、接入协议与检查表、档次 A/B 判定与例外机制；
4. 统一入口内的身份上下文与页面级/接口级权限呈现（判据由服务端持有）；
5. Studio 作废后的工作台壳层职责承接（过渡期以 Hermes/PMC/GPCF Console 分担，见替代方案 §2）。

**非范围（out）**：

1. 业务主账、运行引擎、治理裁决、项目协作、Agent 运行时；
2. 各项目仓内代码改造与验收（属主项目执行）；
3. 真实生产发布、共享/生产实例写入、客户验收；
4. 任何项目 `accepted` / `integrated` / `production_ready` / `customer_accepted` 声明；
5. 微前端容器（Module Federation / wujie）——按设计要求**第一阶段不做**，留作第三步按需试点。

## 4. 目标架构（P0 四项为不变量）

分层（五层，自下而上）：

```
L1 ui-tokens     令牌单一来源（tokens.css / semantic.css / tokens.ts）
L2 ui-kit        组件收敛层（22 件直出 + 状态/证据/AI 边界等编排组）
L3 app-shell     外壳/骨架（GlobalCloudShell / Sidebar / Topbar / TitleBar；capabilities 默认全关 + slots）
L4 app-registry  应用注册与入口导航（app 条目 / entry / requires / legacy 别名）
L5 host-kit      宿主能力（身份 IdP、写门禁、装配态、本地进程等；dev 由 vite 中间件承载）
```

P0 四项架构不变量：

| # | 架构不变量 | 契约要点 | 证据口径 |
|---|---|---|---|
| **O1** | 外壳解耦 | 纯壳 + `capabilities` **默认全关** + `slots` 显式注入；`describeShellComposition()` 可自检"壳是否干净" | 单测（默认全关/旧 `aiPanel` 等价 `slots.rightPanel`/空入参 clean=true）+ E2E（不传参无右侧面板、默认动作区不变） |
| **O2** | 令牌收口 | `ui-tokens` 单一来源（76 令牌 baseline）；`semantic.css` 只新增别名不覆盖；迁移期双命名 `--x` / `--color-x` | 令牌集合与 `TOKEN_NAMES` 一致；跨项目复制件逐字节相同（工具校验）；T1 零视觉回归（接入项目执行） |
| **O3** | 侧栏统一 | 框架内**唯一导航侧栏**；WAME `FunctionPanel` 等业务面板以插件/槽位形态存在；应用切换器全页唯一 | 单测 + E2E（`toHaveCount(1)`）；项目侧归并按批次判据 |
| **O4** | 状态语义层 | 7 值字典（`running/blocked/partial/review/complete/candidate/human_required`）；S1 未映射不得进入统一外壳；S2 GCPF 门禁词不折算 `complete`；S3 AI 产出必须携带来源回指 | 单测（字典稳定/每值有标签与令牌/未映射→unmapped 且不可进壳/门禁词→gcpc_gate）+ E2E（显式标注） |

补充架构要求（2026-10-22 实测发现的收敛缺口，属 O1/O3 的延伸，纳入实施但**不改变 P0 定义**）：

- `app-registry` → `AppsShell` 导航层必须按服务端 `/me.menus` 收敛：`generated.ts` 的 app/entry 需带 `requires`，否则 `canSee()` 恒真、viewer 仍见受限入口（**页面/接口判据已正确拒绝，不构成越权成功**）。
- 页面级权限呈现："没这功能"与"你没权限"必须区分（无权限时明确提示，不假装成功、不显示空表）。
