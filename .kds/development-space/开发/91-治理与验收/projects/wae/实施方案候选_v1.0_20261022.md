## 2. 实施原则

1. **先证据后状态**：每个任务包必须有命令与可回放证据，`pass` 只写给真实通过的项；
2. **单载体**：本期 WAE 的实施只通过 F-034 承载；不另立并行 Feature 改同一范围；
3. **不改他仓**：WAE 仓内改动由 WAE 属主执行；PKC/Brain/PVAOS 等目标项目改造属其属主（本方案只给协议/判据）；
4. **每步过 UI gate**：涉界面改动的轮次必须留证（Tool route / Context package / Prompt profile / Design options / Selected option / WAME baseline reuse 六件套），关键门禁 G1/G4/G5/G8/G9 不得失败；
5. **不把计划写成完成**：M0–M3 全部为计划态；当前 WAE 仓内 `VERIFICATION.md` 自测记录（V6–V16 等）为 B 级文档声明，未经 F-034 复跑前不得作为完成依据；
6. **状态上限**：确认前 WAE 保持 `candidate` / `pending_unique_plan`，`status_ceiling=partial`；任何提升需人工确认。

## 5. P0 四项任务包（命令 / 证据 / 门禁 / 回滚）

### O1 外壳解耦

- **目标**：纯框架壳可独立运行；WAME 专属能力（FunctionPanel / RightAIAssistantPanel / WASM / 性能监控 / 项目持久化）全部以 `capabilities`（默认全关）或 `slots` 注入。
- **命令**：`pnpm --filter @globalcloud/wame exec vite --port 4300`（或 `pnpm dev`）→ `pnpm test` / `pnpm typecheck`；E2E：`npx playwright test --config <F-034 evidence>/playwright.config.ts --grep "shell"`。
- **证据**：`shellCapabilities` 单测（默认全关、`aiPanel≡slots.rightPanel`、`describeShellComposition()` 空入参 clean=true）；独立入口 E2E（无右侧面板、默认动作区不变）；WAME 能力全关回归。
- **门禁**：G1 Surface Structure / G8 Runtime Verification；UI gate 六件套。
- **回滚**：capability 关闭即恢复母本行为；壳件按 `BASELINE.md` 直出清单逐件回退；无后端/数据变更。

### O2 令牌收口

- **目标**：`ui-tokens` 单一来源（76 令牌 baseline）；语义层只新增别名；迁移期双命名 `--x`/`--color-x`。
- **命令**：`pnpm test`（tokens 单测）；`python3 -c` 包装的跨项目校验（仓内既有 `tools/verify-token-sources.py` 或等价脚本）；接入项目侧执行 T1 像素/结构比对。
- **证据**：令牌集合与 `TOKEN_NAMES` 一致；`default_theme.css` 不再声明令牌；复制件逐字节相同；PKC 4 处、Brain 30 处 + 5 独有令牌的偏离逐项裁定记录。
- **门禁**：G1；T1 零视觉回归（接入项目侧执行）；偏离不得静默。
- **回滚**：复制件保留至 B4 收敛后；接入项目 import 退回本地复制件即恢复；语义层为纯别名可撤。

### O3 侧栏统一

- **目标**：框架内唯一导航侧栏；WAME `FunctionPanel`（1557 行）以插件/槽位形态存在；应用切换器全页唯一；项目侧三套（`FunctionPanel` / `components/Sidebar.tsx` / `layout/GlobalCloudSidebar.tsx` 49 行）按批次归并。
- **命令**：`pnpm test` / `pnpm typecheck`；E2E：应用切换器 `toHaveCount(1)`、无第二侧栏、移动端抽屉行为。
- **证据**：框架侧 E2E + WAME 首例归并回归；项目侧归并记录（WAME 先行，PKC/Brain/PVAOS 随批次）。
- **门禁**：G1/G8；例外（确需独立侧栏）走三方审批（GPCF+WAE+目标项目）。
- **回滚**：关闭 capability 恢复母本侧栏；未归并的项目保持原样。

### O4 状态语义层

- **目标**：7 值状态字典 + `StatusBadge` + 语义令牌；S1 未映射不得进壳；S2 GCPF 门禁词不折算 `complete`；S3 AI 产出带来源回指（本仓无 AI 产出类组件时记录为 N/A）。
- **命令**：`pnpm test`（字典 11 例级）；E2E（未映射/门禁词显式标注、不出现"已完成"折算）。
- **证据**：字典稳定、每值有标签与两令牌、未映射→`unmapped` 且 `canEnterUnifiedShell()=false`、6 门禁词→`gcpc_gate`。
- **门禁**：G4 Evidence And Governance / G5 AI Fact Separation；S1/S2 代码级判定。
- **回滚**：字典/令牌/`StatusBadge` 均为框架新增件（非母本直出），撤回使用点不影响母本。

### 附：AppsShell 角色收敛修复（2026-10-22 实测缺口）

- **缺口**：`apps/wame/src/app/apps/generated.ts` 的 app/entry 无 `requires` → `AppsShell.canSee()` 恒真 → viewer 仍见服务控制台入口（页面/接口判据已正确拒绝，不构成越权成功）。
- **任务**：①生成器从 `placement.city.yaml` 的 `requires` 输出到 `generated.ts`；②E2E：viewer 不显示受限入口、system-admin 可见；③接口 403 与页面提示一致。
- **证据**：F-010 已实测的双角色脚本（`F-010/evidence/ui-gates-20261022/wae-multi-user.spec.ts`，system-admin 16 menus / viewer 4 menus / users API 200 vs 403）可作回归基线；F-034 需复跑并归档新证据。
- **门禁**：G9 Scope Control + multi_user gate；**回滚**：`requires` 为增量字段，回退生成器与 `generated.ts` 即恢复原状（原缺陷回归）。

## 7. 验收标准

1. **功能/质量**：F-034 `verification.tests/build` 真实复跑（`pnpm test` / `pnpm typecheck` / `pnpm build`），失败如实记 fail；
2. **UI gate 六件套** + 关键门禁 G1/G4/G5/G8/G9 均记录且无失败；
3. **角色收敛**：viewer 登录后不显示受限入口；system-admin 可见；页面提示与接口 403 一致（双角色 E2E）；
4. **无机器字段暴露**：默认界面可见文本不含 `doc_id` / `evidence:` / JSON / 内部 ID（沿用 F-010 扫描口径）；
5. **接入协议与检查表**落盘；PKC 首个接入演练完成但**不声明已接入**；
6. **状态**：Feature 至多 `ready_for_review`；项目状态提升与 `accepted/integrated/production_ready/customer_accepted` 必须人工确认，不在本方案内；
7. **证据归档**：F-034 `evidence/` 下 tests/build/screenshots/api/summary + `verification` 命令输出；UI 证据（截图/结构指标/断言 JSON）可回放。
