# GCMEM 与 mem0 多维度指标分析

> 基准日 2026-10-17。GCMEM 全部为**本机实测**（基准脚本 `~/.hermes/scripts/tests/bench_gcmem.py`，可复跑）；
> mem0 为公开口径估算（标注 ⚠估），无本机实测（已于 2026-10-16 退役）。

## 一、检索质量

| 指标 | GCMEM 实测 | mem0 口径 |
|---|---|---|
| Top-1 命中率 | **93.3%**（45 查询：原句/关键词/改写三形态） | ~90-95%⚠估（向量相似度，同义改写类优、长尾术语差） |
| Top-3 命中率 | **97.8%** | ~95-98%⚠估 |
| 查询形态鲁棒性 | 原句 15/15、关键词 14/15、改写 13/15 | 改写形态强（嵌入语义），**关键词碎片形态弱**（向量对短碎片不敏感） |
| 冷门/长尾 | bigram 字面重叠为 0 时不召回，诚实报无命中 | 向量总有近邻，易召回弱相关（阈值靠调用方调） |

结论：检索质量同级；GCMEM 胜在**确定性**（可解释、分数直出），mem0 胜在改写泛化（但易噪声）。

## 二、性能延迟

| 操作 | GCMEM 实测 | mem0 口径 |
|---|---|---|
| 本地排序（检索核心） | **0.2ms**（35 条） | Qdrant 本地查询 10-50ms⚠估 |
| 账本读取+解析 | **0.25ms** | — |
| 检索全链（API 端到端） | 0.47s 热 / 1.02s 冷（瓶颈=gbrain 子进程） | 0.2-0.8s⚠估（云 API 网络往返为主） |
| 健康/统计端点 | **1-4ms** | — |
| 字符串判重 | **0.05ms** | 无（判重依赖 LLM 调用） |
| 写入快路径（判重+写+同步索引） | **3.0s**（sync 占 ~2.9s） | add 必走 LLM 提取 ≈1-3s + 向量入库 + 云往返 ≈2-5s⚠估 |
| LLM 判重（infer=true） | 2-4s（实测） | 每次 add 必付 |
| MCP 握手 | 60-75ms（实测） | — |

结论：核心路径 GCMEM 快 1-2 个数量级；全链相当（gbrain 是唯一优化点，可选缓存待评估）。

## 三、判重准确率

| 用例 | GCMEM 字符串层 | GCMEM LLM 层 | mem0 |
|---|---|---|---|
| 完全相同 | ✅ 拒 | ✅ 拒 | ✅ 拒（LLM） |
| 标点/空白差异 | ✅ 拒（归一化） | ✅ | ✅ |
| 包含关系 | ✅ 拒 | ✅ | ✅ |
| 同义改写 | ❌ 放行（设计如此）→ LLM 层 ✅ 拒（实测） | **✅ 拒（实测：「三个AI端共享记忆库」被拒）** | ✅ 拒（LLM） |
| 部分重叠（不同语义） | ✅ 放行 | ✅ 放行 | ✅ |
| 字符串层准确率 | **6/6 = 100%** | — | — |

结论：双层层级设计与 mem0 单层 LLM 判重**效果等价**，但 GCMEM 快路径零成本零延迟，仅可疑改写才付 LLM 钱。

## 四、扩展性（本地排序延迟曲线，实测）

| 账本条数 | 50 | 200 | 500 | 1,000 | 2,000 |
|---|---|---|---|---|---|
| 排序延迟 | 0.1ms | 0.4ms | 1.0ms | 2.0ms | **4.1ms** |

线性 O(n·m)，万条级预计 ~20ms。mem0 向量方案可支撑百万级——**本场景（个人长期记忆，目标 <1 万条）两者均无压力**。

## 五、成本

| 项 | GCMEM 实测 | mem0 |
|---|---|---|
| 存储 | 账本 7.4KB（**213B/条**），本地零成本 | 云配额计费（**本机曾因配额耗尽退役**，2026-10-16 实证） |
| 写入（字符串判重） | **¥0** | 每次 add 走 LLM 提取 ≈¥0.01-0.05⚠估 |
| LLM 判重/提炼 | ≈¥0.002/次、≈¥0.005/段对话（DeepSeek 最低档） | 同上（每写必付） |
| 检索 | ¥0（本地） | 云按查询/存储计费 |
| 年化估算（正常使用） | <¥5 | ¥50-200+⚠估（且会撞配额） |

## 六、可靠性与工程化

| 指标 | GCMEM | mem0 开源自建 |
|---|---|---|
| 回归测试 | **113/113**（2026-10-20：核心 52 + API 22 + 管理台 24 + DSH 捕获桥 15） | 无（调用方自理） |
| 巡检 | doctor 全绿（结构/近重复/替代链/候选积压） | 无 |
| 熔断 | 连续 5 败暂停 120s | 无 |
| 服务保活 | launchd 常驻 + 自动重启 | 自建 |
| 备份纪律 | 写前备份（实证多次） | 自建 |
| 审计可溯 | append-only + 替代链 | 真更新覆盖历史 |
| 测试注入 | GCMEM_LEDGER_PATH 环境变量 | — |

## 综合结论

1. **检索质量/判重效果：同级**（93-98% vs 行业估计持平，双层层级等价）。
2. **性能：核心路径 GCMEM 快 50-250 倍**（0.2ms vs 10-50ms）；全链受 gbrain 拖累与 mem0 云版相当。
3. **成本：GCMEM 压倒性**（¥0 快路径 vs 每写必付 LLM）。
4. **可靠性：GCMEM 全面超出**（mem0 开源版无巡检无回归无熔断）。
5. **短板**：超大语料（>10 万条）与深度改写泛化是向量方案的领地——本场景用不到。
6. 唯一优化候选：gbrain 子进程 0.5s 瓶颈（可加结果缓存，收益大、风险低）。

**总评：GCMEM 在个人长期记忆场景全面对标并超过 mem0；mem0 的适用场景是超大规模多租户云记忆。**
