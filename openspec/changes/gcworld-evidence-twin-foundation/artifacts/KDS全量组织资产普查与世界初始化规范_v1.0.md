# KDS全量组织资产普查与世界初始化规范

## 一、目的与适用范围

本规范定义如何从KDS事实来源形成GCWORLD组织资产候选、关系证据和可审计的世界初始化输入。它适用于人员、法人组织、非法人团队、政府机构、客户、合作伙伴、员工、项目组织及其职能关系。

本规范不构成KDS写入、身份自动合并、权限授予、外部系统调用、部署或验收授权。

## 二、基本原则

1. **来源先闭环**：每个可发现来源必须具有唯一处置记录，不得因格式、敏感性或解析失败而静默遗漏。
2. **先判级后读取**：在打开正文前先根据独立授权和路径规则确定读取边界；未知或冲突按最严格等级处理。
3. **证据与身份分离**：来源提及只能生成候选，不能自动生成正式世界资产。
4. **不确定性不扩权**：候选、目标和模拟状态不得扩大真实权限或直接成为事实。
5. **最小披露**：S3只保留授权允许的不可逆索引和复核状态，不输出路径、正文、片段、预览、记忆或向量。
6. **确定性可复放**：相同授权、快照和规则必须生成逐字节一致的台账。
7. **零写入默认**：普查阶段不得修改来源，不得调用KDS、MMC或业务系统写接口。

## 三、来源闭环模型

每个来源必须进入下列一种处置状态：

| 状态 | 定义 | 后续动作 |
| --- | --- | --- |
| 已解析 | 在授权等级内完成本地解析 | 提取未决候选和关系证据 |
| S3受控索引 | 仅登记不可逆标识、摘要、介质、大小和复核状态 | 进入人工复核，不提取候选 |
| 技术排除 | 秘密文件、缓存、数据库、链接、二进制技术来源等 | 保持隔离，按类型处理 |
| 格式例外 | 损坏、加密、Git LFS指针、格式不支持或超限 | 记录明确原因，不静默跳过 |
| 范围排除 | 不属于批准快照或来源清单 | 不读取，并记录范围依据 |

来源闭环最低字段包括：不可逆来源标识、路径摘要、内容摘要、介质类型、字节大小、分级、分级理由和复核状态。S0—S2可在授权范围内增加原始相对路径和解析状态；S3不得增加这些字段。

## 四、分级与读取规则

1. 以授权文件、独立路径分类、显式文档标级和内容风险信号共同判定，结果取最严格等级。
2. 路径分类缺失、冲突或内容无法可靠解析时，不得降低等级。
3. Git LFS指针不是原始文档，必须作为明确格式例外，不得交给PDF或Office解析器。
4. 符号链接必须登记但不得跟随；链接目标内容不属于当前来源快照。
5. Office开放格式只读取允许的内部XML成员；必须防止路径穿越和压缩炸弹。
6. 读取必须避免符号链接替换和扫描期间文件变化；发现变化立即阻断整轮结果。

## 五、候选资产契约

候选必须至少包含：

- 稳定候选标识；
- 候选类型：人员或组织；
- 来源中的显示名称；
- 身份处置状态：固定为“未决候选”；
- 正式世界资产标识：固定为空；
- 来源证据引用和来源摘要；
- 关系证据引用列表。

稳定候选标识只在同一来源、候选类型和显示名称组合内稳定。跨来源同名不得自动合并，以避免把重名人员、同名组织或集团内不同法人错误合一。

## 六、身份归一与人工裁决

身份归一必须依次完成：

1. 验证来源证据真实存在且未被撤销；
2. 判断候选类型和名称提取是否正确；
3. 查找权威锚点，例如统一社会信用代码、正式任职记录或经确认的主体编号；
4. 对名称、别名、曾用名、简称和跨语言名称形成显式别名关系；
5. 对冲突证据保留并标注，不得用后写记录覆盖历史事实；
6. 由指定人工责任人确认合并、拆分、驳回或保持未决；
7. 形成事实提升候选，交由WAES和独立写入授权处理。

任何缺少权威锚点的身份不得生成正式 `worldAssetId`。人工确认也不能替代后续写入授权和治理门禁。

## 七、关系证据与双时间

每条关系候选必须引用存在的主体候选和来源证据，记录关系谓词、对象、证据状态与来源摘要。任职、合作、服务、审批和代表关系在进入事实世界前还必须补齐：

- 有效时间：现实世界中何时成立和失效；
- 记录时间：系统何时知道该事实；
- 证据强度和冲突状态；
- 授权范围、组织范围和项目范围；
- 撤销、替代或继承关系。

缺少时间或证据的关系只能保持候选，不得被工作台展示为确定事实。

## 八、四类世界初始化边界

| 世界 | 可接收内容 | 禁止事项 |
| --- | --- | --- |
| 事实世界 | 已确认身份、正式关系、有效授权和可追溯证据 | 接收未决候选或模拟结果 |
| 运行世界 | 当前任务、行动、结果、反馈和临时运行状态 | 独立扩大事实权限 |
| 目标世界 | 计划组织、目标关系和期望状态 | 被当作已发生事实 |
| 模拟世界 | 基线快照、假设、分支结果和风险评估 | 复用事实标识、直接写回或授予真实权限 |

本轮普查产物只属于“事实提升前的候选层”，不属于上述四类世界中的正式资产。

## 九、例外队列处置标准

例外必须具有稳定例外标识、来源不可逆标识、路径摘要、分级、通用原因码和复核状态。处置顺序如下：

1. 秘密、凭据和个人敏感信息：保持S3，不读取正文；需要独立授权和专门运行身份。
2. Git LFS指针：核验本地LFS对象是否存在；未取得内容授权前不拉取、不解析。
3. 损坏或加密文件：由来源责任人确认可恢复版本和合法解密边界。
4. 不支持格式：新增解析器前必须先写失败测试、资源上限和安全测试。
5. 链接和外部目标：只登记链接本身；外部目标必须作为新来源重新授权。
6. 疑似误报候选：保留原证据，记录驳回理由，不删除历史审计记录。

## 十、验收指标

一轮普查只有同时满足以下条件，才可声明“来源层普查完成”：

- 来源处置覆盖率为100%；
- 来源标识和路径摘要唯一；
- 所有例外具有明确原因和责任队列；
- 两次运行的总账和输出摘要完全一致；
- 扫描前后来源元数据全等；
- KDS、MMC和业务系统写入均为0；
- S3输出字段白名单核验通过；
- 候选与关系引用完整。

只有进一步达到身份归一率100%、冲突和例外全部裁决、事实提升通过独立治理与写入授权，才可评估“组织资产世界初始化完成”。任何较低状态都必须标记为 `partial / rework`。

## 十一、本轮基线

截至2026年8月23日，本轮已满足来源层普查完成条件：42,971个来源全部处置，两轮结果一致，来源修改和外部写入均为0。但87,043个人员或组织候选全部未决，17,338个S3/例外项待复核，身份归一率为0%。因此本轮不满足组织资产世界初始化完成条件。
