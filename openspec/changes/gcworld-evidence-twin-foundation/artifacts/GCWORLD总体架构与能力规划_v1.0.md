# GCWORLD 总体架构与能力规划

## 一、定位与建设原则

GCWORLD 是 GlobalCloud 项目群的证据驱动世界运行体系。它不是三维展示界面，也不是 OA、CRM、项目管理和知识图谱的简单拼接，而是以真实组织资产为主体、以关系和事件为运行骨架、以 KDS 事实证据为依据、以智能体为协同执行单元的统一世界投影与工作台。

GCWORLD 必须同时满足五项原则：

1. 每个人、组织、团队、项目、系统及其他世界对象都使用稳定资产标识表达；同一主体的不同职能以角色和职能智能体表达，不复制出多个“人”。
2. 人员、组织和关系的任何事实结论必须能追溯到 KDS 证据；未决别名和身份冲突必须进入例外队列，不能静默合并。
3. 事实世界、运行世界、目标世界和模拟世界严格隔离；不确定信息只能收紧真实权限，不能扩大权限。
4. GCWORLD 维护可重建的世界投影，不成为第二事实主账；真实动作仍由相应业务系统执行。
5. 所有智能体动作必须绑定身份、角色、授权、世界快照、风险、确认、结果和证据，做到可拒绝、可撤销、可补偿、可追责。

“不遗漏任何人或组织”不是设计声明，而是覆盖评估结论。只有在批准的 KDS 来源完成确定性普查，并对未决、重复、排除及敏感来源逐项登记后，才能报告具体覆盖率；当前文档不得被解释为已经完成全量覆盖。

## 二、系统职责边界

| 系统 | 唯一职责 | 不得承担的职责 |
| --- | --- | --- |
| KDS | 保存知识事实、来源证据、版本和正式确认记录 | 不直接承载工作台运行态，不因智能体推断自动改写事实 |
| WAS-Ontology | 定义资产、关系、事件和流的权威语义 | GCWORLD 不复制其八维资产和八流权威枚举 |
| GCWORLD | 构造版本化世界快照、投影组织关系、呈现统一工作台和运行上下文 | 不成为权限事实源，不直接替代业务系统写入 |
| XWAIL | 提供职能智能体的理解、规划、协同和建议能力 | 不自行获得真人全部权限，不把推断提升为事实 |
| WAES | 根据身份、授权、风险和策略作出确定性裁决 | 不替代执行点落实权限，不直接修改业务主账 |
| MMC | 在授权范围内连接模型、工具和外部能力 | 不自行扩权，不保存新的组织事实主账 |
| 业务系统 | 执行 CRM、项目、财务、合同、供应链等真实业务动作并返回回执 | 不绕过 WAES 扩权，不自行伪造 GCWORLD 世界状态 |
| LOOP | 编排变更、任务、证据和复盘闭环 | 不替代独立验收结论 |
| Harness | 独立验证证据、门禁和最终状态 | 不代替业务责任人批准真实动作 |

## 三、核心世界模型

### 3.1 世界资产与身份

世界资产至少包含稳定标识、WAS 维度引用、身份状态、显示名、权威来源或候选来源、生命周期和证据引用。正式标识由稳定来源锚确定，名称、别名、抓取时间和证据顺序不得改变标识。

身份状态至少分为“已确认”和“未决”。未决人员或组织可以保留多个候选来源，但不得进入事实关系、正式授权或真实行动链。身份合并和关系争议的最终人工裁决人当前为项目发起人老卢；该责任不等于授权系统自动执行合并。

### 3.2 关系与双时间

关系用于表达任职、成员、客户、合作、服务、汇报、授权、委托、依赖和影响等结构。每条关系同时保存：

- 现实有效时间：关系在现实世界何时成立和失效；
- 系统记录时间：系统何时获知、登记和修订该关系。

角色变更通过明确的前后继关系连接。新任关系生效时，原关系必须具有可解释的结束边界；同一主体同时承担多个合法角色不构成冲突，是否冲突由职责分离和授权策略判断。

### 3.3 四类世界状态

| 世界 | 含义 | 对真实权限和事实的影响 |
| --- | --- | --- |
| 事实世界 | 已有正式证据支持的人员、组织、关系和状态 | 可作为正式授权输入，但仍需通过 WAES 策略 |
| 运行世界 | 当前任务、承诺、行动、反馈、风险和协同状态 | 可触发限制、冻结或审批，原则上不能独立扩权 |
| 目标世界 | 计划、预算、里程碑和预期结果 | 仅用于规划，不产生真实权限或事实 |
| 模拟世界 | 基于基线快照和假设集的分支推演 | 只能生成事实提升候选，禁止直接回写或授权 |

模拟记录必须包含分支标识、基线快照和假设引用；事实提升必须重新经过证据、规则与人工确认门禁。

## 四、职能智能体与世界原生权限

每个职能智能体必须绑定一个组织资产角色，并登记责任人、来源范围、运行模式、能力范围、风险上限、证据要求、确认要求和禁止动作。运行模式依次为镜像、辅助、委托和自治；“自治”只表示在已批准信封内自动运行，不代表获得无限权限。

有效权限是主体权限、角色任用、授权或委托、智能体契约、目标资产策略、项目情境、WAES 门禁和实时风险的交集。身份、角色定义、角色任用、授权契约、运行裁决和执行回执必须分别建模，不能用一个静态角色包代替。

对外沟通、资金、合同、身份合并、权限、政府沟通和业务状态变更默认禁止。未来如需开放，必须具有独立授权、必要人工确认、短期裁决凭证、提交前再次验证和可级联撤销机制。

## 五、世界运行闭环

标准运行链为：

```text
观察来源 → 解析候选 → 关联证据 → 构造世界快照 → XWAIL 规划
→ WAES 裁决 → 必要人工确认 → MMC/业务系统执行 → 行动回执
→ KDS 事实提升候选 → LOOP 复盘 → Harness 验证
```

每次运行必须保留世界快照版本、身份版本、策略版本、授权版本、资源版本、命令标识、幂等键、因果标识、结果、异常和补偿证据。跨系统操作采用可重试、可去重、可补偿的事件与命令，不使用无法追溯的同步长事务伪装全局一致。

## 六、GCWORLD 工作台

工作台基于同一世界模型形成十二个工作中心：

1. 世界总览中心；
2. 组织资产中心；
3. 关系网络中心；
4. 客户与伙伴中心；
5. 项目与任务中心；
6. 承诺与行动中心；
7. 职能智能体中心；
8. 权限与责任中心；
9. 证据与知识中心；
10. 事件与反馈中心；
11. 模拟实验中心；
12. 治理与审计中心。

所有中心复用同一资产标识、世界快照和权限上下文。单一资产档案统一呈现事实、历史、别名、关系、角色、授权、任务、行动、结果、反馈、证据、冲突和模拟分支。字段、段落、图节点、图边、搜索、时间线、统计、导出和智能体回答必须执行一致的权限裁剪，防止通过聚合或推断泄露受限信息。

## 七、数据与工程底座

GCWORLD 数据分为来源、候选、KDS 正式事实、世界投影、运行状态、模拟分支、证据与审计七层。任何状态提升必须经过显式规则，不允许由图数据库、搜索索引、缓存或向量库反向成为事实。所有派生存储必须能够从 KDS 事实、事件和版本化契约重建，并通过差异检测证明没有产生第二事实账本。

本轮已形成机器可读的资产、别名、关系、证据和世界状态 Schema，并用三组正例、四组反例验证稳定标识、证据引用、关系双时间、未决身份和模拟隔离。WAS 维度仅保存权威引用；在无法解析正式注册表时明确报告“语义未解析”，不得自行发明第二套本体。

## 八、实施路线与阶段门禁

| 阶段 | 目标 | 退出条件 |
| --- | --- | --- |
| P0 | 架构、术语和契约冻结 | OpenSpec 严格校验、文档门禁、机器模型与反例通过 |
| P1 | KDS 组织资产只读普查 | 来源清单完整、零写入、未决与排除可复核、覆盖率可计算 |
| P2 | 只读世界运行时 | 投影可重建、快照可版本化、图和索引非事实主账 |
| P3 | 内部辅助智能体 | 仅建议和草稿、行动信封完整、执行账本可审计 |
| P4 | GCWORLD-AUTH | 动态裁决、职责分离、提交前复核、级联撤销通过 |
| P5 | 模拟实验室 | 分支隔离、假设可追溯、事实提升候选受门禁控制 |
| P6 | 受控真实执行 | 独立授权、人工确认、幂等回执和补偿演练通过 |
| P7 | 有限自治与扩域 | 场景级风险上限、持续监控和随时撤销能力通过 |

阶段状态依次受结构合规、验证就绪、待人工验收和完成门禁约束。任何智能体不得自行宣布“已验收”“已集成”“生产就绪”或“全量覆盖”。

## 九、当前授权与阻塞结论

用户已确认对 KDS 全部知识空间执行元数据普查，S0—S2 内容仅可本地只读分析，S3 仅登记存在性并由人工复核；老卢暂任身份与关系争议最终裁决人。本授权不包含 KDS API、KDS 写入、业务系统写入、身份自动合并、部署、提交发布或状态提升。

当前 KDS 工作树存在未处置变更且本地分支领先远端，F-013 读取准入门禁为阻断。因此本轮只完成授权固化、模型契约和本地确定性样例，不执行 KDS 内容普查，不报告人员或组织全量覆盖率。解除条件是由 KDS 责任方独立处置工作树和本地提交，并形成新的可复核只读快照。

## 十、交付与验收口径

本规划与机器模型属于 GPCF 内的草案和验证证据。下一阶段的真实完成标准包括：批准来源全部进入来源台账；每个人和组织均为已归一、未决、重复候选或明确排除之一；所有关系具有证据与有效时间；输出可重复生成且 KDS 文件修改数为零；独立 Harness 完成复核。

在上述条件满足前，准确结论只能是“架构契约已建立、全量内容普查仍受阻”，不能表述为 GCWORLD 已完成、已上线或已经映射全部现实组织资产。
