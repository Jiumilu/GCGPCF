# GCWORLD第一批优先人工复核包责任主体接受授权请求

## 一、请求事项

请求批准进入第一批优先人工复核包的责任主体识别与接受节点。输入仅限SHA‑256为`cd06236075b7b9b9098a75ef6190dc6fd7d2258eb7e2865c27197949d2d50ced`的二十个S2复核包，覆盖五项多类型冲突和十五个同名候选组，共三十五个复核项。

本请求只申请：

1. 使用既有项目、组织、人员、任务、线程和授权元数据，逐包提名真实业务主复核责任主体；
2. 核验责任主体的身份、角色、授权依据、复核范围、有效期和利益冲突；
3. 仅向核验通过并明确接受责任的主体交付对应S2复核包；
4. 记录主复核接受或拒绝状态；
5. 主复核接受后，再向F‑013发起独立第二复核接受确认。

## 二、责任路由原则

| 复核对象 | 主责任路由 |
| --- | --- |
| 自然人身份争议 | 人事、项目负责人或关系责任人 |
| 法人或市场主体争议 | 法务、商务或企业登记责任人 |
| 政府或公共机构争议 | 政府关系、项目联络或合规责任人 |
| 其他组织或跨域冲突 | GKE‑001整理后动态路由至适用业务责任人 |
| 第二复核 | F‑013独立复核线程 |
| 重大争议最终裁决 | 老卢 |

不能验证真实业务责任人的复核包继续保持未决，不发送、不启动SLA，也不得由GKE‑001、F‑013或老卢自动替代日常主复核责任。

## 三、每名责任主体必须明确声明

1. 责任主体名称或组织资产标识；
2. 权威角色及授权依据；
3. 可验证身份或签名线程；
4. 承担的复核包标识与范围；
5. `valid_from`与`valid_until`；
6. 目标受众与业务敏感边界；
7. 分发约束、撤销或到期条件；
8. 利益冲突声明；
9. 明确接受或拒绝主复核责任。

任一字段缺失、依据不可验证、责任范围冲突或主体拒绝接受时，对应复核包继续保持未决。

## 四、明确不授权事项

本请求不授权读取新的KDS正文、数据库、接口、凭据或业务数据，不授权自动身份合并、正式世界资产生成、KDS写入、事实提升、权限授予、测试、服务变更、提交、推送、部署或状态提升。

责任主体接受只意味着可以开始人工复核，不意味着身份建议已被批准。SLA只能在真实主复核责任主体完成核验并明确接受、F‑013接受第二复核责任且复核包证据边界完整后启动。

## 五、精确人工批准用语

批准严格按照SHA‑256为`cd06236075b7b9b9098a75ef6190dc6fd7d2258eb7e2865c27197949d2d50ced`的二十个S2优先人工复核包，使用既有项目、组织、人员、任务、线程和授权元数据识别并核验真实业务主复核责任主体；仅向核验通过且明确接受责任的主体交付对应复核包，并在主复核接受后向F‑013发起独立第二复核接受确认。未找到可验证责任人、声明字段不完整、授权依据不可验证、存在责任冲突或主体拒绝接受时，对应复核包继续保持未决且不启动SLA。该批准不授权读取新的KDS正文、自动身份合并、正式世界资产生成、KDS写入、事实提升、权限授予、测试、服务变更、提交、推送、部署或状态提升。
