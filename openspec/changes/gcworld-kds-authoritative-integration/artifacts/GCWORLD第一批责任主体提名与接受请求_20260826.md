# GCWORLD第一批责任主体提名与接受请求

## 一、请求目的

本请求将第一批一千零十六个高频身份复核项划分为六个互斥责任包，要求为每个责任包提名一个可验证的人员或组织资产，并由被提名主体明确接受或拒绝。未完成提名、授权核验和接受回执前，不得启动五个工作日SLA，不得开展身份裁决。

本请求不自动指定老卢或任何现有人物为执行责任人。老卢仅沿用历史“临时最终裁决人”角色模型，并且必须在逐项身份决定前重新确认有效性。

## 二、责任包

| 责任包 | 复核项 | 待提名责任角色 |
| --- | ---: | --- |
| 一 | 211 | 候选所属组织的人事、项目或关系责任方 |
| 二 | 306 | 法人登记、商务或法务责任方 |
| 三 | 66 | 政府关系与合规责任方 |
| 四 | 5 | 项目负责人或项目管理责任方 |
| 五 | 38 | 发起组织、章程或成员治理责任方 |
| 六 | 390 | GKE‑001知识工程与身份治理责任方 |

六个责任包合计覆盖一千零十六个复核项，复核项标识互不重复且无遗漏。

## 三、每个责任包必须补齐的提名字段

1. 提名主体名称或组织资产标识；
2. 主体类型：人员或组织；
3. 授权依据；
4. 可验证身份或签名线程；
5. 精确责任范围；
6. 有效起始时间和有效终止时间；
7. 利益冲突声明；
8. 接受或拒绝决定；
9. 接受回执标识；
10. 撤销、到期和无响应处置方式。

任何字段缺失、主体无法验证、授权依据失效、存在未处置利益冲突或主体未明确接受时，该责任包继续保持“待提名”或“待接受”，其复核项不得进入身份决定。

## 五、治理边界

- 历史最终裁决人、第二复核角色和五日SLA模型须在逐项决定前重新确认；
- 责任角色名称不能替代真实人员或组织资产；
- 不得推断责任主体已经接受；
- 不得预填利益冲突声明或接受回执；
- 拒绝、无响应或证据不足时保持待分派，不自动转交其他主体；
- 不读取实时KDS、S3正文或UNKNOWN正文；
- 不执行身份合并、拆分、驳回、KDS写入、事实提升、权限授予或状态提升。
