# GCWORLD第一批优先人工复核责任席位登记请求

## 一、请求目的

现有元数据能够验证GKE‑001协调角色和F‑013第二复核角色，但无法验证二十个优先复核包的真实业务主复核责任主体。为避免把GKE‑001、F‑013或老卢变成日常主复核，本请求建议先登记五类组织级责任席位，再由席位中的实际人员逐包接受责任。

## 二、待登记责任席位

| 责任席位 | 适用范围 |
| --- | --- |
| 人员与关系责任席位 | 自然人身份、岗位、项目关系和联系人争议 |
| 法人、法务与商务责任席位 | 企业、法人、市场主体、合同及商务关系争议 |
| 政府关系与合规责任席位 | 政府部门、公共机构、平台公司及合规边界争议 |
| 项目PMO责任席位 | 项目公司、项目组织和临时联合项目主体争议 |
| 组织治理责任席位 | 非法人团队、协会、委员会、联合体及其他组织争议 |

GKE‑001继续承担机器归一、证据整理和初步责任路由；F‑013继续承担第二复核；老卢仅处理重大争议和最终裁决。

## 三、每个席位必须登记

1. 责任组织资产标识；
2. 席位名称与权威角色；
3. 授权依据；
4. 可验证线程或身份；
5. 责任范围；
6. `valid_from`与`valid_until`；
7. 目标受众和业务敏感边界；
8. 分发约束及撤销条件；
9. 利益冲突处理规则；
10. 当前实际接受人及其接受声明。

未完整登记或未由实际人员接受的席位不能接收复核包，也不能启动SLA。

## 四、明确边界

责任席位登记不产生身份裁决，不授予KDS写权限，不生成正式世界资产，不提升事实或授予业务权限。任何席位都不能批量确认名称相同的候选为同一主体。

## 五、需要人工提供或确认的内容

请为上述五类席位分别提供责任组织资产标识、权威角色、授权依据、可验证线程或身份、有效期和当前接受人。若某类席位暂时无法确定，应明确登记为“空缺”，其对应复核包继续保持未决且不启动SLA。
