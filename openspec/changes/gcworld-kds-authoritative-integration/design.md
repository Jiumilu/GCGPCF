## 背景

KDS是GlobalCloud知识事实主存，GCWORLD只能形成带来源和版本的世界投影。当前全来源受控分级已经完成，但身份候选、关系争议和S3例外仍待人工复核，F‑013实际准入也因KDS工作树持续变化保持阻塞。本设计只定义未来集成的责任边界和门禁，不授权实施。

## 目标与非目标

**目标：**

- 建立从KDS正式事实到GCWORLD投影的可重放、可对账读取链。
- 保留候选、例外、证据、双时间和人工复核状态，不静默合并身份。
- 为未来事实提升建立幂等请求、WAES门禁、人工确认、KDS回执和失败补偿契约。
- 将Feature日志、文档门禁、证据索引和Harness交接纳入每次集成批次。

**非目标：**

- 不在GCWORLD复制KDS事实主账。
- 不读取S3正文，不自动解决全部身份与关系冲突。
- 不因本规划完成而授权KDS写入、API调用、部署或状态提升。

## 设计决策

### 1. 读取与提升使用两条独立通道

正式事实读取通道只消费经过授权的KDS快照；候选提升通道只提交带证据的请求，不能直接修改事实。采用该方案是为了让只读投影与高风险事实变更拥有不同授权、凭据和审计链。未采用双向自动同步，因为它会模糊事实主存并扩大错误合并风险。

### 2. 每次批次绑定不可变准入快照

批次必须记录KDS提交、远端关系、工作树摘要、F‑013准入结果、授权摘要、分级清单、本体版本和投影版本。任一版本变化即使旧令牌仍有效也必须重新准入。未采用长期缓存准入，因为当前KDS状态会被本地服务持续改变。

### 3. 候选与例外保持显式状态机

候选依次处于待复核、证据不足、冲突、批准、拒绝或过期状态；批准只产生提升请求。S3只保存不透明标识和受控指针。未采用“高置信自动合并”，因为名称和关系推断不能替代权威身份裁决。

### 4. KDS责任系统执行最终写入

未来写入必须由KDS受控接口在WAES裁决和人工确认后执行，GCWORLD仅保存请求与回执引用。命令携带幂等键、因果标识、预期版本和证据摘要；版本冲突默认拒绝。

### 5. 证据与状态提升分离

每个批次产生输入清单、输出摘要、差异报告、零写入或写入回执和Harness证据。OpenSpec完成最多说明规划或结构就绪，不改变F‑013、Release或产品状态。

## 风险与权衡

- [KDS持续变化导致快照过期] → 每次运行前重新执行F‑013准入并绑定短有效期快照。
- [候选复核积压] → 按风险和影响排序，未复核项保持候选，不阻塞无关只读事实。
- [S3元数据可推断敏感信息] → 使用不透明标识、最小字段和单独访问审计。
- [投影与事实不一致] → 支持全量重建、摘要比对和差异阻断。
- [误把提案当授权] → 任务首项要求独立Feature、仓库、接口和写入授权，未满足时不得开始实现。

## 迁移计划

1. 独立批准Release、后继Feature、目标仓库、责任人和只读接口范围。
2. 在干净且已准入的KDS快照上实现只读适配器和对账，不启用写入。
3. 完成人工候选队列、S3例外和差异复核后，再申请受控提升接口授权。
4. 仅在Harness与人工确认后，小范围启用幂等提升请求并验证回滚。
5. 任一门禁失败即停用集成凭据、冻结批次并从KDS事实重建投影。
