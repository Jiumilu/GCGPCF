## 背景

GCWORLD基础变更已验证运行时结构、风险分级和失败样例，但真实执行数、真实授权数和外部写入数均为0。当前GKE‑001只有报告模式，没有获准的产品运行线路。本设计定义未来从镜像观察到受控执行的集成方式，不授权启动任何服务。

## 目标与非目标

**目标：**

- 建立服务职责、世界快照、裁决、确认、执行、回执和证据的完整链。
- 通过R0—R4门禁和阶段开关确保权限逐级收窄。
- 为重复命令、部分失败、超时、撤销和补偿提供确定性处置。
- 形成可观测指标、Feature日志、Evidence Index与Harness交接。

**非目标：**

- 不在规划阶段部署服务、申请凭据或连接真实系统。
- 不允许GCWORLD替代WAES裁决、MMC连接或业务系统执行。
- 不直接进入自治模式，不为未确认候选授予真实权限。

## 设计决策

### 1. 运行闭环采用不可跳步状态机

动作按观察、解析、快照、推理、裁决、确认、执行、取证、提升和学习推进。每一步保存输入摘要、版本、结果和失败原因；缺少裁决或确认时不能生成成功回执。未采用智能体直接调用连接器，因为无法证明授权与责任链。

### 2. 服务使用短期运行身份和能力交集

真人会话、智能体调用、运行身份、连接器凭据和业务动作逐层分离；有效能力取主体、角色、授权、智能体契约、资源策略、情境和风险门禁的交集。任何上下文不完整默认只读或拒绝。

### 3. 写执行采用可靠命令和补偿

命令携带命令标识、幂等键、因果标识、关联标识、快照版本和失效时间；执行系统使用收件去重、事务发件、重试、死信和补偿回执。未采用跨系统长事务，因为它扩大故障半径且无法覆盖外部系统。

### 4. 阶段开关与风险级别双重控制

第一阶段只允许R0镜像和R1建议；R2内部写入、R3外部动作和R4重大行动分别要求新的Feature、授权、确认和Harness门禁。阶段开关不能扩大单次WAES裁决。

### 5. 真实执行必须产生责任回执

每个允许、拒绝、失败、撤销和补偿都形成不可变回执，关联主体、代表关系、智能体、裁决、确认、执行系统和结果。没有回执的动作不得标记成功。

## 风险与权衡

- [服务过多增加复杂度] → 首期使用清晰模块边界实现单体纵向切片，契约保持可拆分但不预建微服务。
- [缓存裁决过期] → 高风险动作提交前重新验证快照和短期裁决。
- [部分失败造成重复副作用] → 使用幂等键、执行回执和经批准的补偿策略。
- [紧急授权被滥用] → 仅短时、双人确认、硬审计并强制事后复核。
- [结构测试冒充运行] → Harness分别要求真实服务、真实裁决、真实连接器和目标系统回执。

## 迁移计划

1. 独立批准Release、后继Feature、目标仓库、责任人、服务范围和测试环境。
2. 实现无外部连接器的R0镜像闭环，验证快照、裁决拒绝和证据记录。
3. 接入测试WAES和人工确认，仍保持所有执行连接器禁用。
4. 在独立授权下逐项启用R2测试动作，再分别评审R3和R4。
5. 回滚时关闭阶段开关、撤销运行身份和凭据、停止任务并核对未完成回执。
