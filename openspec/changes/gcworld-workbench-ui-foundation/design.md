## 背景

GCWORLD基础变更已定义十二个工作中心、单一资产档案和全链路权限裁剪，但尚无产品实现。上轮Harness明确将UI、中文搜索和真实数据链标记为不适用。本设计将未来界面限定为同一世界投影的受控视图，并与KDS事实、WAES裁决和XWAIL智能体边界分离。

## 目标与非目标

**目标：**

- 建立十二中心统一导航和稳定的资产、项目、快照与权限上下文。
- 让事实、运行、目标、模拟、候选、冲突和受限状态可区分、可解释。
- 对字段、关系、搜索、统计、导出和智能体回答使用同一裁剪结果。
- 形成中文、可访问、可测试的响应式界面基线及Harness证据。

**非目标：**

- 不在本变更中选择或修改真实产品仓库。
- 不接入真实客户数据，不开放写操作或跨租户共享。
- 不以原型截图替代API、权限、数据链和运行证据。

## 设计决策

### 1. 十二中心共享同一应用外壳和上下文

导航层只改变视图，不创建各自的人员、组织和项目主数据。路由状态必须携带资产标识、世界快照、租户、组织、项目和权限裁决引用。未采用独立微应用先行，因为它会在语义和权限尚未稳定时产生多个主数据副本。

### 2. 单一资产档案作为主要交互枢纽

人物、组织、团队、项目、角色、智能体和系统使用统一档案骨架，按类型显示事实、历史、关系、授权、任务、行动、证据和冲突。未决身份保持候选卡片，不与正式档案合并。

### 3. 状态语义同时使用文字、形状和颜色

所有关键状态使用中文标签、图标或形状及颜色三重表达，避免仅靠颜色。模拟和目标使用持续可见的分支/计划标识，候选显示“待复核”，受限内容不通过计数或布局暴露。

### 4. 权限裁剪在视图模型层统一执行

服务端视图模型先按WAES裁决裁剪，再交付界面；客户端只负责呈现，不把隐藏当权限控制。搜索、统计、导出和智能体回答共享同一裁决及快照。

### 5. 先验证只读纵向切片

首个实现候选只覆盖世界总览、组织资产、关系网络和项目世界四个中心，以及单一资产档案。其他中心保留导航与空状态契约；任何动作按钮均为禁用或草稿，直到运行时另行授权。

## 风险与权衡

- [十二中心同时设计导致范围过大] → 先交付四中心纵向切片，其余只定义契约。
- [图谱看起来可信但证据不足] → 默认显示证据状态、有效期、冲突和来源入口。
- [前端隐藏造成伪安全] → 裁剪在服务端完成，客户端测试只验证一致呈现。
- [统计泄漏受限关系] → 对聚合设置最小群组、模糊化或完全隐藏，并记录裁决。
- [提案被当作产品完成] → Harness必须区分原型、固定数据、集成数据和真实运行四类证据。

## 迁移计划

1. 独立批准产品仓库、后继Feature、设计责任人、数据契约和测试环境。
2. 使用固定契约数据实现四中心只读纵向切片并完成中文与可访问性测试。
3. 经WAES裁剪契约验证后连接获准的只读GCWORLD视图接口。
4. 真实搜索、跨租户共享、导出和动作入口分别经过安全与Harness门禁。
5. 回滚时关闭功能开关并移除界面路由，不改变世界事实或业务系统。
