## 1. 产品授权与基线

- [ ] 1.1 批准所属Release、后继Feature、产品仓库、产品与设计责任人、线程和有界文件范围。
- [ ] 1.2 确认首批用户角色、四中心纵向切片、屏幕范围、中文规范、可访问性等级和验收环境。
- [ ] 1.3 批准固定契约数据、只读视图接口、租户范围、脱敏规则、凭据和功能开关。
- [ ] 1.4 复核现有设计系统、组件库和路由架构，记录复用边界而不另建重复体系。

## 2. 测试先行的界面基础

- [ ] 2.1 为跨中心资产、项目、快照和权限上下文保持编写失败测试。
- [ ] 2.2 为事实、运行、目标、模拟、候选、冲突和受限状态的中文及非颜色表达编写视觉语义测试。
- [ ] 2.3 为字段、图、搜索、统计、导出和智能体回答的一致裁剪编写负向泄漏测试。
- [ ] 2.4 为只读阶段的动作禁用、草稿边界和缺失授权提示编写交互测试。

## 3. 四中心纵向切片

- [ ] 3.1 实现统一应用外壳、十二中心导航、面包屑和世界上下文切换。
- [ ] 3.2 实现世界总览、组织资产、关系网络、项目世界及单一资产档案的固定数据版本。
- [ ] 3.3 实现证据、有效时间、冲突、可信等级、模拟假设和裁决依据的解释入口。
- [ ] 3.4 完成键盘导航、焦点、对比度、缩放、响应式和中文长文本验证。

## 4. 只读数据与权限集成

- [ ] 4.1 获得数据集成独立授权后，接入经批准的只读GCWORLD视图接口并固定契约版本。
- [ ] 4.2 验证服务端裁剪先于界面呈现，客户端隐藏不会替代权限控制。
- [ ] 4.3 验证搜索、统计、导出和跨中心跳转不会泄漏受限实体、边或数量。
- [ ] 4.4 保持跨租户共享和所有真实动作关闭，直至各自获得单独授权与运行时回执能力。

## 5. 验证、证据与回滚

- [ ] 5.1 执行单元、组件、构建、格式、类型、可访问性、响应式和浏览器端到端检查。
- [ ] 5.2 验证GKE‑001 Program与CodeGraph绑定；只有真实消费关系变化时才更新权威映射。
- [ ] 5.3 更新Feature日志、Evidence Index、验收矩阵和中文文档，并通过OpenSpec严格校验及项目群文档门禁。
- [ ] 5.4 演练关闭功能开关、移除路由和回退只读视图契约，不修改世界事实或业务系统。
- [ ] 5.5 将结构、固定原型、只读集成、权限集成和真实运行证据分级提交Harness独立复核。
