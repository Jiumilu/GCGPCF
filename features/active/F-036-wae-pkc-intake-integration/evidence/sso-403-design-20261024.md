# F-036 生产嵌入 SSO/403 设计预案

## 1. 现状

- WAE 侧已有身份服务（本地目录 + OIDC/飞书可插拔）；PKC 独立部署，dev 通过 iframe 直接加载。
- 生产 iframe 面临：跨站 Cookie、SSO 会话不共享、PKC 401/403 可能表现为白屏、CSP `frame-ancestors` 需白名单。

## 2. 候选方案

| 方案 | 做法 | 风险 |
|---|---|---|
| A. 同 IdP 会话 | PKC 接同一 OIDC IdP；iframe 依赖第三方 Cookie | 浏览器第三方 Cookie 限制；需 SameSite=None; Secure |
| B. 父页 token 握手 | WAE 生成短时 token，postMessage 给 PKC；PKC 换会话 | 需严格 origin 校验、token 一次性、CSP；实现成本中 |
| C. 服务端代理 | WAE 反代 PKC 同源 | 需网关/路由与鉴权；跨团队改造大 |
| D. 只做只读展示 | PKC 提供匿名只读页，敏感操作禁在 iframe | 功能受限，但最快可用 |

## 3. 最小要求（任一方案）

1. `frame-ancestors` 只允许 WAE 正式域名。
2. iframe 内 401/403 必须可读提示，不得白屏/静默。
3. 不在 URL 放 token/凭据；postMessage 校验 origin。
4. 回滚：关闭 embed URL 即回到候选页。

## 4. 建议

- 先做方案 B 的最小闭环（只读 + 单角色），再评估方案 A/C。
- 需 WAE/PKC 属主共同签字；本轮不实现，仅记录设计。

## 5. 非声明

- 不声明 SSO 已对齐；不声明生产可用。
